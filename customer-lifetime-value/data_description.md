# Data description

All data is **synthetic**, generated by `src/data_generator.py` with a fixed seed (42). Ranges below describe how the generator is built, not statistics from a real business.

Dates use the format `YYYY-MM-DD`.

## Table `data/customers.csv`

One row per customer (1,200 rows).

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `customer_id` | integer | Unique customer identifier, assigned in order of acquisition date | 1 to 1200 |
| `acquisition_date` | date | Date the customer was acquired (also the date of the first order) | 2024-01-01 to 2025-06-30 |
| `acquisition_channel` | string (category) | Channel through which the customer was acquired | `organic`, `paid_search`, `social`, `email`, `referral` |
| `country` | string (category) | Customer country | `US`, `UK`, `DE`, `FR`, `ES` |

## Table `data/transactions.csv`

One row per order. The generator raises an error if the table would exceed 5,000 rows.

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `transaction_id` | integer | Unique order identifier, assigned in order of date | 1 to number of rows |
| `customer_id` | integer | Customer who placed the order (foreign key to `customers.customer_id`) | 1 to 1200 |
| `transaction_date` | date | Date of the order | from the customer's `acquisition_date` up to 2025-12-31 |
| `order_value` | float | Order revenue in a single generic currency unit, rounded to 2 decimals | at least 5.00, no fixed upper bound (right-skewed) |

## Relationships and notes

- `transactions.customer_id` references `customers.customer_id`; every customer has at least one order (the first order on the acquisition date).
- Purchase behavior follows a BG/NBD-like process: each customer has a latent purchase rate and a latent probability of becoming inactive after each purchase. These latent parameters are **not** saved to the CSV files.
- The observation window ends on 2025-12-31, so customers acquired later have less observed history.
- Acquisition channel slightly shifts the purchase rate (for example, `email` and `referral` customers buy somewhat more often than `social` customers).
