# Data Description

All data is **synthetic**, generated by `src/data_generator.py` (numpy, seed 42). Reference date ("snapshot") for all time-based columns: **2024-12-31**.

Files are written to `data/`.

## Table `customers.csv` (4000 rows)

One row per customer.

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `customer_id` | int | Unique customer identifier (primary key) | 1 to 4000 |
| `signup_date` | date (YYYY-MM-DD) | Subscription start date, equal to snapshot minus `tenure_months * 30` days | approx. 2020-01-27 to 2024-12-01 |
| `tenure_months` | int | Months since signup at the snapshot date | 1 to 60 |
| `age` | int | Customer age in years | 18 to 80 |
| `country` | string | Country of residence | US, UK, Germany, France, Canada, Australia |
| `contract_type` | string | Contract commitment | Month-to-month, One year, Two year |
| `plan` | string | Subscription plan | Basic, Standard, Premium |
| `payment_method` | string | Main payment method | Credit card, Debit card, PayPal, Bank transfer |
| `auto_renew` | int (0/1) | 1 if automatic renewal is enabled | 0, 1 |
| `discount_flag` | int (0/1) | 1 if the customer has a 15% discount | 0, 1 |
| `monthly_price` | float | Monthly price in USD: plan base price (9.99 / 14.99 / 24.99), reduced by 15% if discounted | 8.49 to 24.99 |
| `avg_weekly_logins` | float | Average number of logins per week | 0.0 to 30.0 |
| `avg_session_minutes` | float | Average session length in minutes | 3.0 to 90.0 |
| `late_payments_6m` | int | Number of late payments in the last 6 months | 0 to 6 |
| `churned` | int (0/1) | **Target.** 1 if the customer cancelled, 0 if still subscribed | 0, 1 |

No missing values in this table.

## Table `support_tickets.csv` (4500 rows)

One row per support ticket. Linked to `customers.csv` through `customer_id` (many tickets per customer are possible; many customers have none).

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `ticket_id` | int | Unique ticket identifier (primary key) | 1 to 4500 |
| `customer_id` | int | Foreign key to `customers.customer_id` | 1 to 4000 |
| `created_date` | date (YYYY-MM-DD) | Date the ticket was opened (within the 180 days before the snapshot) | 2024-07-04 to 2024-12-31 |
| `category` | string | Ticket topic | Billing, Technical, Account, Feature request |
| `priority` | string | Ticket priority | Low, Medium, High |
| `resolution_hours` | float | Hours until the ticket was resolved | 0.5 to 240.0 |
| `satisfaction_score` | int, nullable | Customer satisfaction rating after resolution (1 = very unhappy, 5 = very happy). Empty if the customer did not respond (about 15% of tickets) | 1 to 5, or missing |

## Notes

- Churn depends on contract type, tenure, price, logins, late payments, discount, auto-renew and a hidden customer "frustration" factor. The factor is not saved, but it also drives the number of support tickets a customer files.
- The actual churn rate and the share of missing satisfaction scores are printed when the generator runs.
