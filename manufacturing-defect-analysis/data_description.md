# Data Description

All data is **synthetic**, generated by `src/data_generator.py` (numpy, seed 42). Files are saved in `data/`.

Where a range is given as "clipped", the generator enforces it. Otherwise the range is the set of allowed values by construction.

## Table: `production_batches.csv`

One row per inspected production batch. 2000 rows, ordered in time (8 batches per day, 250 days starting 2025-01-01).

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `batch_id` | string | Unique batch identifier | `B00001` to `B02000` |
| `production_date` | string (date, YYYY-MM-DD) | Date the batch was produced | 2025-01-01 to 2025-09-07 |
| `shift` | string (category) | Work shift | `Morning`, `Afternoon`, `Night` |
| `line` | string (category) | Production line | `Line_A`, `Line_B`, `Line_C` |
| `machine_id` | string (category) | Machine that produced the batch (three machines per line: Line_A = M01-M03, Line_B = M04-M06, Line_C = M07-M09) | `M01` to `M09` |
| `operator_id` | string (category) | Operator in charge | `OP01` to `OP20` |
| `supplier` | string (category) | Supplier of the raw material | `Supplier_X`, `Supplier_Y`, `Supplier_Z` |
| `product_type` | string (category) | Product variant | `Type_A`, `Type_B`, `Type_C` |
| `units_inspected` | integer | Number of units inspected in the batch (subgroup size) | 40 to 60 |
| `defects_count` | integer | Number of defective units found | 0 to `units_inspected` |
| `defect_rate` | float | `defects_count / units_inspected`, rounded to 4 decimals | 0 to 1 |
| `temperature_c` | float | Process temperature in degrees Celsius | clipped to 185 to 215 |
| `pressure_bar` | float | Process pressure in bar | clipped to 4.4 to 5.6 |
| `avg_diameter_mm` | float | Average measured diameter of the critical dimension in mm (nominal 25.0) | clipped to 24.9 to 25.1 |

No missing values are generated.

## Table: `defects.csv`

One row per defective unit. The number of rows for a batch equals its `defects_count`, so batches with zero defects do not appear. The generator stops with an error if the table would exceed 5000 rows.

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `defect_id` | string | Unique defect identifier | `D00001` upward, sequential |
| `batch_id` | string | Batch where the defect was found (foreign key to `production_batches.batch_id`) | Existing `batch_id` values |
| `defect_type` | string (category) | Type of defect | `Scratch`, `Dimensional`, `Crack`, `Porosity`, `Discoloration` |
| `severity` | string (category) | Severity of the defect | `Minor`, `Major`, `Critical` |
| `repair_cost_usd` | float | Repair or scrap cost in US dollars, rounded to 2 decimals | clipped to 1.00 to 500.00 |

No missing values are generated.

## Relationships

- `defects.batch_id` references `production_batches.batch_id` (many defects to one batch).
- For every batch, the count of rows in `defects.csv` equals `defects_count`.

## Built-in data-generating mechanisms (for transparency)

The data is simulated, so the mechanisms below are known by design. They are not findings.

- Base defect probability per unit is 2%, multiplied by factors for the night shift, `Supplier_Z`, operator `OP13`, temperature above 200 °C, and the shifted-diameter condition on machine `M07`.
- Machine `M05` has a gradual upward temperature drift starting at day 150.
- Machine `M07` has a step shift in average diameter starting at day 160.
- The defect type mix depends on batch conditions (for example overheating favours `Porosity` and `Crack`, `Supplier_Z` favours `Crack`, the diameter shift favours `Dimensional`).
- Severity and repair cost depend on defect type and severity.
