# Manufacturing Defect Analysis

Statistical process control (SPC) charts and defect root-cause analysis on a synthetic production dataset.

> **Note:** All data in this project is **synthetic**. It is generated by `src/data_generator.py` with a fixed random seed (42). It does not describe any real factory, product or supplier.

## Business question

Which production factors (machine, shift, material supplier, operator, process settings) drive the defect rate, and is the production process statistically in control over time?

## Goal

- Monitor the process with SPC control charts (for example p-chart for defect rate, X-bar chart for diameter) and flag out-of-control signals.
- Identify the most likely root causes of defects and the defect types they produce.
- Estimate the cost of defects and show where corrective actions would matter most.

## Plan of the work

1. **EDA**: check data quality, distributions, defect rate over time, and breakdowns by line, machine, shift, supplier and operator.
2. **Analysis / model**:
   - SPC control charts with control limits and rule-based signal detection.
   - Root-cause analysis: Pareto analysis of defect types, statistical tests across groups, and a regression model of defect probability on the candidate factors.
3. **SQL**: analytical queries (defect rate by factor, worst machines, cost by defect type) in the `sql/` folder.
4. **Tests**: `pytest` checks for the data generator (schema, ranges, reproducibility, row limits) and for the analysis functions.

## Dataset (synthetic)

Two CSV tables are written to `data/`:

| Table | Rows | Description |
|-------|------|-------------|
| `production_batches.csv` | 2000 | One row per inspected production batch, with context, process settings and defect counts |
| `defects.csv` | at most 5000 (checked by the generator) | One row per defective unit found, with defect type, severity and repair cost |

Several effects are built into the generator so that root-cause analysis has something to find: a temperature drift on one machine, a diameter shift on another machine after a certain date, a lower-quality supplier, a higher defect rate on the night shift and for one operator. Whether and how strongly the analysis recovers these effects is reported only once the analysis has actually been run.

Full column descriptions are in [`data_description.md`](data_description.md).

## How to run

Run everything from the project root.

```bash
pip install -r requirements.txt
python src/data_generator.py
```

The generator creates the `data/` folder if needed and overwrites the CSV files on each run (the output is identical every time because of the fixed seed).

To run the tests (once they are added):

```bash
pytest tests
```
