# Data Description

All data is **synthetic**, generated by `src/data_generator.py` with a fixed seed (42). It does not represent real customers or transactions. Ranges below follow from how the generator is built (clipping and sampling limits).

## Table: `customers` (`data/customers.csv`, 1,000 rows)

One row per customer.

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `customer_id` | int | Unique customer identifier (primary key) | 1 to 1000 |
| `age` | int | Customer age in years | 18 to 80 (normal distribution, clipped) |
| `country` | string | Customer's home country code | `US`, `UK`, `DE`, `FR`, `ES` |
| `account_age_days` | int | Days since the account was opened | 30 to 3649 |
| `monthly_income` | float | Monthly income in currency units | 1,000.00 to 20,000.00 (log-normal, clipped) |
| `credit_limit` | int | Card credit limit, a multiple of income rounded to the nearest 100 | at least 500 |

## Table: `transactions` (`data/transactions.csv`, 5,000 rows)

One row per card transaction, ordered by time.

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `transaction_id` | int | Unique transaction identifier (primary key), increasing with time | 1 to 5000 |
| `timestamp` | string (datetime, `YYYY-MM-DD HH:MM:SS`) | When the transaction happened | 2025-01-01 00:00:00 to 2025-06-30 23:59:59 |
| `customer_id` | int | Customer who made the transaction (foreign key to `customers.customer_id`) | 1 to 1000 |
| `amount` | float | Transaction amount in currency units | 1.00 to 5000.00 (log-normal, clipped; fraud has larger amounts) |
| `merchant_category` | string | Type of merchant | `grocery`, `restaurant`, `fuel`, `retail`, `travel`, `electronics`, `entertainment`, `health` |
| `channel` | string | How the card was used | `pos`, `online`, `atm` |
| `is_foreign` | int (0/1) | 1 if the transaction took place outside the customer's home country | 0 or 1 |
| `new_device` | int (0/1) | 1 if an online transaction came from a device not seen before; always 0 for `pos` and `atm` | 0 or 1 |
| `distance_from_home_km` | float | Distance between the transaction location and the customer's home, in km | 0.0 to 8000.0 |
| `is_fraud` | int (0/1) | Target label: 1 if the transaction is fraudulent | 0 or 1 (exactly 100 rows with 1, i.e. 2% by design) |

## Notes on how fraud is simulated

Fraudulent transactions are drawn from different distributions than legitimate ones:

- larger amounts;
- more activity at night (hours 0 to 5 and 22 to 23);
- mostly online, with more purchases in electronics, travel and retail;
- more often foreign and from a new device;
- larger distances from home.

The distributions overlap, so no single feature separates the classes perfectly.
