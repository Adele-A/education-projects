# Data description

All data is **synthetic**, generated by `src/data_generator.py` (numpy, seed 42). It does not describe any real warehouse. The ranges below are the bounds enforced by the generator.

## Table `data/pickers.csv`

One row per picker (60 rows).

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `picker_id` | string | Unique picker identifier | `P001` to `P060` |
| `experience_months` | integer | Picker's experience in months | 1 to 120 (temp workers: 1 to 24) |
| `contract_type` | string (category) | Type of employment contract | `full_time`, `part_time`, `temp` |

## Table `data/orders.csv`

One row per picked order (5000 rows).

| Column | Type | Meaning | Value range |
|--------|------|---------|-------------|
| `order_id` | string | Unique order identifier | `O00001` to `O05000` |
| `picker_id` | string | Picker who picked the order (foreign key to `pickers.picker_id`) | `P001` to `P060` |
| `order_date` | string (date, `YYYY-MM-DD`) | Date the order was picked | 2025-01-01 to 2025-03-31 (90 days) |
| `shift` | string (category) | Work shift | `morning`, `afternoon`, `night` |
| `priority` | string (category) | Order priority | `standard`, `express` |
| `n_lines` | integer | Number of order lines (distinct items) | 1 to 40 |
| `n_units` | integer | Total number of units to pick (at least `n_lines`) | 1 to 600 |
| `total_weight_kg` | float | Total order weight in kilograms | 0.1 to 500.0 |
| `n_zones` | integer | Number of warehouse zones visited (at most `n_lines`) | 1 to 8 |
| `distance_m` | float | Walking distance during picking, in meters | 10.0 to 600.0 |
| `pick_time_min` | float | Total picking time in minutes (target variable) | 0.5 to 240.0 |

## Notes

- Orders are drawn from four latent profiles (small, medium, bulk, multi-zone). The profile label is **not** saved in the data.
- Picking time grows with distance, lines, units, weight and zones. It is lower for more experienced pickers and about 8% higher on the night shift, with random noise on top.
- `order_date`, `shift` and `priority` are generated independently of each other.
