# Data Description

All data is **synthetic**, generated by `src/data_generator.py` (numpy, seed 42). Value ranges below are those enforced by the generator's code. Dates are ISO strings (`YYYY-MM-DD`).

## customers.csv
One row per customer (500 rows by construction).

| Column | Type | Meaning | Value range |
|---|---|---|---|
| customer_id | string | Unique customer key | `C00001` .. `C00500` |
| age | integer | Customer age in years | 21 to 70 |
| region | string | Customer region | North, South, East, West, Central |
| employment_status | string | Employment status | Employed, Self-employed, Retired, Unemployed |
| annual_income | integer | Annual income in currency units | 18000 to 250000 |
| credit_score | integer | Credit score at application | 450 to 850 |
| credit_segment | string | Segment derived from the credit score | Prime (>= 720), Near-Prime (640-719), Subprime (< 640) |

## loans.csv
One row per loan (400 rows by construction). Each loan belongs to a different customer, so `customer_id` is unique here.

| Column | Type | Meaning | Value range |
|---|---|---|---|
| loan_id | string | Unique loan key | `L00001` .. `L00400` |
| customer_id | string | Foreign key to `customers.customer_id` | existing customer ids |
| origination_date | string (date) | Date the loan was issued | 2024-09-01 to 2025-06-28 |
| product_type | string | Loan product | Personal Loan, Auto Loan, Home Improvement, Small Business |
| principal | integer | Original loan amount | 2000 to 80000, in steps of 100; the range depends on the product |
| interest_rate | float | Annual nominal interest rate, % | 5.00 to 30.00 |
| term_months | integer | Contractual term in months | 12, 24, 36, 48 or 60, depending on the product |
| risk_grade | string | Risk grade derived from the credit score (A = best) | A, B, C, D, E |
| monthly_payment | float | Level annuity payment | positive, rounded to 2 decimals |

## loan_snapshots.csv
One row per loan per month-end, from the first month-end after origination until the loan is paid off, charged off, or the as-of date is reached. The table is capped at 5000 rows, and the generator asserts this.

| Column | Type | Meaning | Value range |
|---|---|---|---|
| loan_id | string | Foreign key to `loans.loan_id` | existing loan ids |
| snapshot_date | string (date) | Month-end date of the snapshot | 2024-09-30 to 2025-12-31 |
| months_on_book | integer | Months since the origination month (1 = first month-end after origination) | 1 to 16 |
| balance | float | Outstanding principal balance at the snapshot; 0 for paid-off loans; balance at the time of charge-off for charged-off loans | 0 to 80000 |
| dpd_bucket | string | Delinquency bucket, days past due | Current, 1-29, 30-59, 60-89, 90+ |
| status | string | Loan status at the snapshot | active, paid_off, charged_off |

Notes:
- A `paid_off` or `charged_off` row is the last row for that loan.
- A `charged_off` row always has `dpd_bucket` = `90+`; a `paid_off` row always has `dpd_bucket` = `Current` and `balance` = 0.
- Balances are held flat while a loan is delinquent (a simplification); interest on delinquent loans is not accrued.
- Delinquency states follow a Markov chain whose roll rates depend on `risk_grade`, so worse grades become delinquent more often.
